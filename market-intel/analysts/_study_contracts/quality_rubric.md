# 품질 루브릭 — 「참조 write-up 급」이 되려면 통과해야 하는 항목 
과거 케이스에서 사용자가 고쳐 준 것들을 검사 항목으로 옮겼다. 각 항목 = PASS/FAIL, 실패는 사유. 이 표를 통과하지 않은 산출은 사용자에게 내지 않는다(무배경 편집장 서브가 먼저 채점).

## A. 내러티브·질문 (S0)
- [ ] A1 시장이 믿는 이야기가 원천(누가·등급)과 함께 2개 이상 적혀 있고, 「가격에 반영됐나」 칸이 있다
- [ ] A2 우리 가설마다 test·metric·falsify 가 있다 — 「이해가 있어서 검증에 들어갔다」의 증거
- [ ] A3 핵심 질문 3~5 가 「답이 곧 뷰」인 질문이다(피크 매출·확장 계획·퀄리티·뷰·확신 요인 급)
- [ ] A4 본체가 approved_by 를 채웠고 사용자에 내러티브 한 문단을 먼저 보고했다

## B. 검증·데이터 (S1)
- [ ] B1 1차 원천 우선(DART·공시·통계), 셀사이드는 「시장 뷰」로만, 회사 전망은 「회사 주장」
- [ ] B2 선례 케이스 스터디가 있다(예: 신시장 진출 선례 n건 → 꺾임 시점 중앙·낙폭의 원인) — 스케일 상한·시점을 선례로 잰다
- [ ] B3 대체 데이터가 「동행인가 선행인가」를 재고 적었다(예: 상관 r 과 시차로 판정)
- [ ] B4 축을 갈랐다: 물량·금액, 반기누계·분기, 리스 회계, 기준 변경(K-IFRS 1118), 수정주가·원주가
- [ ] B5 「없다」는 질의 커버리지와 함께, 「못 잰다」와 「없다」를 구분
- [ ] B6 불일치 표가 있다(원천 간·우리 간 — 예: 원천 간 사채 누락, 카드 간 순차입 정의 차이)

## C. 모델·케이스·배수 (S2)
- [ ] C1 케이스는 축 변수의 값이지 확률의 이름이 아니다(예: 핵심 변수 값 × 분기 경로 2~3), 경쟁 같은 것은 다이얼
- [ ] C2 배수는 믹스가 아니라 **같은 성장 국면 창의 중앙값**(국면 창별 사분위 병기), 12개월 뒤 시장이 볼 성장률에 맞춤
- [ ] C3 사다리에 「우리 뷰」 케이스 하나가 표시되고, 가격이 어느 케이스를 할인하는지 한 줄
- [ ] C4 민감도로 EPS 드라이버와 배수 드라이버를 갈라 적었다(예: 기존 시장 = EPS, 신시장 = 배수)
- [ ] C5 성장률 정점은 전 계열에서 찾았다(표 첫 열을 정점이라 부르지 않는다)
- [ ] C6 세그먼트 합 = OP 를 손으로 더해 이중 차감(EBITDA 에 D&A 재차감)을 잡았다
- [ ] C7 숫자는 전부 계약 파일에서 프로그램으로(손 옮김 0 — 17.5%/17.35% 사고)

## D. 뷰·문장 (S3)
- [ ] D1 두괄식: 각 문항·장의 첫 문장이 답이다. 「트레이딩 바이」처럼 콜의 종류를 명시
- [ ] D2 시장 vs 우리 표 + 「얼마나 더 세게」(우위 없으면 0)
- [ ] D3 틀릴 조건이 관측치·문턱·날짜로 적혀 있고(플립 테이블), 뷰를 거둘 조건이 있다(셋 중 둘)
- [ ] D4 기대 칸은 앞으로 나올 것만(예: 다음 분기 프린트·신규 수주·다음 가격 인상)
- [ ] D5 단서는 각주로, 본문엔 데이터 먼저. 개인 정보·리뷰 본문 없음
- [ ] D6 회사마다 고유 틀(축이 소제목), 참조 양식 과적합 없음

## E. 도표·표·문서 (report-init / notion-pitch)
- [ ] E1 하우스 규격(9×5·Pretendard 6pt·상단 중앙 범례·검은 축·통화 문자 단위), 캡션 = [축] 한 줄 결론 + Source
- [ ] E2 재무표 5 (IS·BS·CF·성장/수익/밸류/KPI·시나리오 값) FY-2~FY+4, 라벨 폭 게이트
- [ ] E3 본문 분량 규약(보고서 표지 논지 ≤ 650단어 급, 문단 첫 문장 = 답)
- [ ] E4 PDF 쪽별 PNG 실견(폰트·잘림), 노션은 정규화 diff
- [ ] E5 도표·표 개수·쪽수를 문면에 적고, 「목표주가 아님」 표기

## F. 트래킹 (S4)
- [ ] F1 레지스터 지표마다 모델 입력(dial)·행동·문턱·다음 날짜
- [ ] F2 기대 원장 초안·촉매 행이 같은 키로 존재
- [ ] F3 첫 채점 이벤트 날짜와 「그 날 무엇을 보나」가 페이지 머리에 있다

## 채점 규약
- 무배경 편집장(Opus, 스터디 맥락 없이 산출물만 읽음)이 A~F 를 채점 → FAIL 항목을 본체가 고친 뒤 사용자에 낸다. 채점표는 packs/<ticker>/QA_<date>.md 에 남긴다.
- 루브릭은 사용자 정정이 생길 때마다 항목을 추가한다.

## G. 밸류체인 위치·사이클 이음매 
- [ ] G1 본문 「Value chain position」 절이 여섯 질문(흐름과 자리 / 누가 누구에게 팔고 누가 내나 / 집중도·대체 / 병목 / Q·ASP·점유 → 매출·마진과 시차 / 몫의 증감 조건)에 **셀사이드 이니시에이션 깊이**로 답한다 — 기준 대형 IB 이니시에이션의 수익 배분 분해(돈의 흐름을 상대 이름·금액·%로 쪼갬). 편집장은 질문마다 「답함 / 서술만 / 없음」을 적고, 「서술만」이 둘 이상이면 FAIL. 회사 소개문(제품 나열)은 답이 아니다
- [ ] G2 S0 3자 내러티브 표(사이클 / 셀사이드 / 무하네스)가 있고, 무하네스에만 있던 주장마다 채택·기각·확인필요와 이유가 있으며, 채택된 것이 본문 어디에 들어갔는지 따라갈 수 있다(SKILL 규칙 45)
